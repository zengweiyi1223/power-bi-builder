## 2. 候选变化裁决

| 候选变化 | 裁决 | 理由 | 位置 |
| --- | --- | --- | --- |
| R-VLD-003 改为风险触发或抽样 | 采纳 | 冗余最终往返边际价值低，但关键生命周期往返发现了真实边界；应按风险选择强度 | Core，仍为 Provisional |
| Desktop 首次保存作为覆盖风险 Human Gate | 采纳 | 首存覆盖了有效外部磁盘修改并写入平台/身份元数据 | Power BI adapter |
| 区分首次保存、关闭—重开和对象加载状态 | 采纳 | 三种状态对外部变更检测和模型加载产生不同结果 | Power BI adapter |
| PBIR-only 与包含 TMDL 的外部修改采用不同路线 | 采纳 | 已加载 PBIR 可 Apply；测试的 TMDL 需重开 | Power BI adapter |
| 区分已加载对象与会话中新对象 | 采纳 | 新视觉未被发现，已加载视觉修改可被检测 | Power BI adapter |
| Human Gate 前置 active/wait/machine 时间 | 条件采纳 | 只有项目声称效率、人时或最少操作时才需要，避免所有项目过度记录 | 新增 Provisional Core Rule + Templates |
| 区分固定生产、条件式生产、诊断、验证专用操作 | 采纳 | 诊断 Run 的 10 次操作不能直接成为生产工作流，偶发风险 Gate 也不应写成每次必做 | 新增 Provisional Core Rule + Templates |
| 重复“无变化”证据压缩为状态转换表 | 采纳 | 保留首末状态和异常即可降低证据噪声 | R-VLD-002 + Validation template |
| 项目文件设置优先于机器全局偏好 | 采纳但不泛化 | 仅验证了 Power BI 模型 annotation 控制当前文件设置 | Power BI adapter |
| MCP 为可选效率路径而非生成前置条件 | 采纳但限定 | V1 证明无 MCP 也能生成；未证明 MCP mutation 无价值 | Power BI adapter |

## 5. 不采纳或延后

- 不把“首次保存后必须重启”写入 Core：这是当前 Desktop 版本的 Power BI 生命周期观察。
- 不把“所有 TMDL 都必须重开”写成无条件结论：V1 只测试一个 measure 修改。
- 不把“所有新 PBIR 对象无法热发现”写成无条件结论：只测试一个新视觉。
- 不把 MCP 从 Power BI 工作流移除：V1 只证明生成不以 MCP 为前置条件，没有否定其复杂模型工程价值。
- 不把项目文件优先于机器全局偏好提升为 Core：当前只有 Auto date/time annotation 的单领域证据。
- 不在 v0.2 确认新增 Provisional Rules 的跨领域有效性；交给后续非 Power BI 项目验证。
