# Power BI Adapter

本文件把通用 Playbook 映射到未来 Power BI 项目。它不修改 V0，也不替代每个实验自己的 REQUIREMENTS 和 VALIDATION。

## 1. Trusted baseline 与 Run

- Trusted baseline 可以是已验证 PBIP/PBIR 种子，也可以是由实验明确要求的空目录；核心方法不预设哪一种成立。
- 种子存在时保持不可变，复制完整项目到唯一 `runs/<run-id>/project/` 后操作。
- `.pbip`、Report、SemanticModel 的名称和相对引用必须一致；正式项目使用业务名称，不沿用 `Seed`。
- `.pbi` 本机设置、缓存和自动恢复文件属于临时状态，不作为正式交付物。

## 2. Contract 映射

Power BI Contract 通常需要冻结：

- Desktop、Modeling MCP、PBIP/PBIR 版本及启用功能。
- 数据源、编码、区域、类型和刷新边界。
- 表、列、关系、度量值、格式和字段绑定名称。
- 页面、视觉对象、布局和交互要求。
- MCP 主路线、允许的 PBIR 修改范围和禁止的人工补改。
- Desktop 打开、保存、关闭、重开和人工视觉确认节点。
- Service 发布、跨机器迁移、凭据和网关是否属于范围。

## 3. Execute–Verify 映射

建议按依赖拆分原子阶段：

1. Git、Trusted baseline、Run 副本和环境检查。
2. MCP 连接及必要能力验证。
3. 固定输入和独立预期结果。
4. 数据加载、Partition 和刷新。
5. 模型对象、属性、关系和度量值回读。
6. DAX 与独立基准比较。
7. 模型持久化往返验证。
8. PBIR 生成、入口、Schema、引用和绑定检查。
9. Desktop 渲染、布局和固定交互验证。
10. Desktop 保存前后语义差异及重开验证。
11. 最终 MCP 回读和代表性 DAX。

项目可删减不适用阶段，但必须说明原因。不得把全部建模、报表生成和 Desktop 验收合并后再一次性验证。

## 4. Human Gate

常见 Human Gate 包括：

- 创建或确认 Desktop 当前文件设置。
- 打开正确 Run 副本，而不是种子原件。
- 处理首次修改、首次查询、隐私和凭据确认。
- 显式保存、关闭和重开 Desktop。
- 确认没有错误、自动修复或异常提示。
- 使用固定步骤验证交互并完成视觉可读性签字。

每次确认应记录目标项目身份，避免把错误窗口或种子当作运行副本。

## 5. 独立验收与证据

- 数值结果优先从原始输入独立计算，不复用 DAX 输出。
- MCP List/Get、DAX 和 Partition 状态用于系统回读。
- PBIP/PBIR JSON、Schema、`byPath`、字段绑定和布局用于静态检查。
- Desktop 实际打开、交互、保存和重开用于真实运行验证。
- 截图用于视觉和交互观察，不替代精确数值日志。
- 保存前后应比较业务语义，不以序列化顺序或换行变化直接判失败。

## 6. 安全与制品

- 日志和截图不得包含账号、令牌、凭据或无关本机信息。
- 本机绝对数据路径可以记录在内部验证中，对外材料应按 Contract 脱敏。
- Power BI 原生 JSON/TMDL/PBIR 的编码和换行策略应在目标版本上核实后固定。
- 正式 Run、关键日志和必要截图默认可追溯；可重建依赖和缓存进入临时目录。

## 7. 停止与归因

- 数据未刷新时不得进入关系、DAX 或报表阶段。
- 模型持久化往返未通过时不得进入 PBIR 阶段。
- Schema 通过不代表 Desktop 通过；Desktop 自动修复也不能冒充完整成功。
- MCP 能力缺失、环境阻塞、实现错误、宿主重写、证据缺口和治理阻塞应分别归因。
- 预览版本或公开 Schema 缺失形成证据限制时，应精确描述能证明和不能证明的内容。
