01 · RESULT

结论先说：能生成，但不是完全无人值守

Codex 可以完成绝大部分工程工作；Power BI Desktop 的生命周期、安全确认和业务签字仍由人负责。

AI 可直接完成

  • 把需求转成模型和页面规格
  • Power Query/M 与 Import Partition
  • 表、关系、日期表和 DAX
  • PBIR 页面、视觉绑定和交互
  • 整理完整 PBIP 项目目录

人工仍需参与

  • 确认业务口径与数据权限
  • 首次创建标准 PBIP 种子
  • 打开、保存、关闭和重开 Desktop
  • 处理确认、凭据和隐私弹窗
  • 最终确认页面符合业务预期

本次实测结果：3 张模型表、2 条关系、5 个 DAX 度量值和 6 个视觉对象均成功进入 PBIP；Desktop 可以打开、筛选、保存和重开。

02 · PATHS

先分清三个路径

很多配置问题来自把 MCP 程序、Power BI 项目和数据源放在同一个概念里。

1

MCP 安装目录

存放 MCP 可执行文件。适合放在稳定、版本化的用户工具目录，不纳入业务项目 Git。

2

PBIP 项目目录

每个报表自己的 `.pbip`、`.Report/` 和 `.SemanticModel/`。它可以位于任意正常工作目录。

3

数据源路径

CSV、Excel 或数据库连接地址。由 Power Query/M 引用，换机器时可能需要重新绑定。

Codex │ 根据配置启动 MCP exe ▼ Power BI Modeling MCP │ 连接当前打开的本地模型 ▼ Power BI Desktop ──读取/保存── PBIP 项目 │ └── Power Query/M ──读取── 数据源

03 · ONE-TIME SETUP

一次性配置 Power BI Desktop

前两项决定项目是否以可外部编辑的 PBIP/PBIR 保存；Auto date/time 设置用于避免隐藏日期表干扰显式日期模型。

必须勾选

Power BI Project `.pbip` 保存选项。

使用增强的元数据格式存储报表（PBIR）。

必须取消

标准种子“当前文件”中的 Auto date/time。

保存种子前再次确认。

建议取消

全局“新文件的自动日期/时间”。

避免以后创建新种子时重复踩坑。

设置预览功能后重启 Desktop。“当前文件”和“全局新文件”是两个设置位置；只改全局设置不能替代对当前种子的检查。

04 · MCP

安装并注册 Modeling MCP

MCP 是 Codex 与 Power BI 模型之间的本地工具桥。它不属于某个 PBIP，也不需要复制到每个项目。

本次实测：微软官方 Windows x64 包 0.5.0-beta.13 安装到版本化用户目录。下次只要 exe 路径和 Codex 注册不变，就可以直接复用。

%LOCALAPPDATA%\Programs\PowerBIModelingMCP\0.5.0-beta.13\ └─ dist\powerbi-modeling-mcp.exe

安装原则

  1. 从微软官方源获取。
  2. 固定版本，不把 `latest` 当作可复现基线。
  3. 放在稳定工具目录，不提交到业务 Git。
  4. 不同版本先运行 `--help` 核对参数。

Codex 注册

  1. 设置 → MCP 服务器 → 添加服务器。
  2. 类型选 STDIO。
  3. 命令填 exe 绝对路径。
  4. 保存后重启 Codex。
  5. 确认 MCP 工具出现在新任务中。
[mcp_servers.powerbi-modeling-mcp] command = "C:\\Users\\<用户名>\\AppData\\Local\\Programs\\PowerBIModelingMCP\\0.5.0-beta.13\\dist\\powerbi-modeling-mcp.exe" args = ["--start", "--require-confirmation"]

以上参数是本次锁定版本的实测配置。其他版本以该版本自己的帮助信息为准。初次使用建议保留写操作确认。

07 · DESKTOP STATE

Power BI Desktop 什么时候开，什么时候关？

把这条时间线记住，可以避开“模型没落盘”和“PBIR 被并发重写”两类问题。

准备运行副本关闭

复制种子与准备数据。

MCP 建模打开

让 MCP 连接本地模型。

模型落盘保存

人工点击保存后关闭。

生成 PBIR关闭

Codex 离线修改报告。

页面确认重开

检查视觉与交互。

09 · DELIVERY

最终交付的是一个项目目录

`.pbip` 主要是入口文件。真正的报告和模型位于两个同级目录，必须整体移动和分享。

YourReport/ ├─ YourReport.pbip ← Desktop 打开入口 ├─ YourReport.Report/ ← PBIR 报表 │ ├─ definition.pbir │ └─ definition/ └─ YourReport.SemanticModel/ ← TMDL 语义模型 ├─ definition.pbism └─ definition/

10 · FAQ

常见问题与当前边界

MCP 要放在项目里吗？

不需要。使用稳定的用户级工具目录更合适，也避免把约 40 MB 的二进制误提交到每个项目。

下一个项目要重新安装吗？

不需要。保持 MCP 路径和 Codex 注册不变；打开新的 PBIP 后重新连接新的 Desktop 实例即可。

为什么还需要人工种子？

这是当前已验证的稳定入口。AI 从空目录直出整个工程壳属于后续零种子实验，尚未写入生产流程。

这已经是无人值守自动化吗？

不是。当前是工程生成高度自动化、Desktop 生命周期与业务授权保留人工控制的人机协作流程。

可以直接发布到 Service 吗？

本教程只交付本地 PBIP。Service 工作区权限、网关、凭据和计划刷新应另走部署流程。

换电脑能直接刷新吗？

本地 CSV 绝对路径和凭据可能需要重新绑定；交付说明中应明确数据源位置与刷新要求。
