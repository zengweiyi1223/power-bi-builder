前置检查、生成与交付

① 前置检查作用：先确认环境，缺条件时提前报告
检查 Power BI Desktop 和当前环境是否支持 PBIP、PBIR、TMDL。生成时显式关闭当前文件的自动日期/时间，并检查官方 Power BI Modeling MCP 是否可用。如需安装、授权、输入凭据或修改设置，先告诉我。
② 数据作用：告诉 Codex 数据在哪里、怎样理解
数据文件：E:\Data\销售明细.xlsx 包含订单日期、产品、品类、销售额、成本和地区。先检查字段、类型、空值和重复记录，不要修改原始数据。
③ 需求作用：说明最后要交付什么
从空目录生成一套可由 Power BI Desktop 打开的完整项目。创建 Overview 页面，展示销售额、毛利额、毛利率、月度趋势和品类贡献，并增加品类筛选器。完成模型、度量值、页面和视觉对象，保留完整 PBIP、PBIR 与 TMDL 文件。
发提示词→Codex 生成→打开→保存→关闭→交付
为什么建议首次保存？不是为了让项目能够打开，而是让 Desktop 完成文件规范化并写入平台、身份等元数据，形成稳定的长期协作与交付基线。
交付什么？不要只发送 .pbip；应交付同级的 .pbip、Report 和 SemanticModel 整个项目目录。移动、提交 Git 或发给他人时保持目录完整，不包含缓存、本机设置、自动恢复文件和临时目录。
