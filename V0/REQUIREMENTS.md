# Power BI Builder — V0 需求文档

## 1. 项目目标

- 通过最小可行实验，验证 Codex 能否结合 Microsoft Power BI Modeling MCP 与 PBIP/PBIR，自动生成可由 Power BI Desktop 正常打开、展示和交互的报表。
- 验证完整链路：自然语言需求 → Codex → Modeling MCP → Semantic Model / DAX → PBIR Report → PBIP → Power BI Desktop。
- 本阶段只验证端到端可行性，不建设完整产品。

## 2. V0 基线方案

- 使用 Power BI Desktop 创建并保存的最小空白 PBIP/PBIR 工程作为种子。
- 种子仅包含有效工程结构、空白语义模型和空白 Overview 页面，不预置目标度量值或视觉对象。
- 语义模型优先通过 Microsoft 官方 Power BI Modeling MCP 创建和修改。
- 报表页面与视觉对象通过公开 PBIR 文件格式生成。
- 不将 Power BI Service 浏览器编辑能力视为本地 PBIP 链路的替代方案。

## 3. 输入数据

- 使用一份项目内的简单销售数据文件，默认格式为 CSV。
- 至少包含：日期、产品键、产品、品类、销量、单价、单位成本。
- 数据规模保持较小，便于人工复核预期结果。
- V0 仅要求在当前实验环境中可打开和刷新；跨机器数据源重绑定不在范围内。

## 4. 语义模型

- 建立最小星型模型：
  - `FactSales`：销售事实数据。
  - `DimDate`：日期维度。
  - `DimProduct`：产品及品类维度。
- 建立关系：
  - `DimDate[Date]` 1 → * `FactSales[Date]`。
  - `DimProduct[ProductKey]` 1 → * `FactSales[ProductKey]`。
- 通过 MCP 重新读取并确认表、列、关系和度量值已生效。

## 5. DAX 度量值

- 至少创建以下 5 个度量值：
  - 销售额：销量 × 单价的汇总。
  - 销量：销售数量汇总。
  - 成本：销量 × 单位成本的汇总。
  - 毛利额：销售额 − 成本。
  - 毛利率：毛利额 ÷ 销售额，并安全处理零销售额。
- 使用 DAX 查询核对总计、月份和品类层级的代表性结果。

## 6. PBIR 报表

- 创建 1 个页面，名称为 `Overview`。
- 页面包含 6 个视觉对象：
  - 3 个 KPI 卡片：销售额、毛利额、毛利率。
  - 1 个销售趋势图：日期 × 销售额。
  - 1 个品类分析图：品类 × 销售额。
  - 1 个切片器：日期或品类。
- 保持基础、清晰、可读的布局，不加入复杂主题、书签、钻取或自定义视觉对象。
- 切片器应能影响 KPI 和分析图表。

## 7. 输出物

- 可直接由 Power BI Desktop 打开的完整 PBIP 项目。
- 输入销售数据及必要的种子文件。
- 模型、DAX、PBIR 和 Desktop 验证记录。
- Demo 结论，明确列出：
  - 已跑通环节。
  - 未跑通环节及原因。
  - 已知限制和后续建议。
- V0 过程产生的所有文件统一存放在本目录内。

## 8. 执行与验证原则

- 首先检查当前环境、Power BI Desktop、PBIP/PBIR 设置和 Modeling MCP 可用性。
- 固定并记录 Power BI Desktop 与 Modeling MCP 版本。
- 每完成一个阶段立即验证，失败时停止后续依赖步骤并记录问题。
- 验证顺序：环境 → 模型 → DAX 数值 → PBIR 结构 → Desktop 打开与交互。
- PBIR 自动生成受限时如实记录，不以复杂替代方案掩盖失败。
- 不用直接编辑 TMDL 冒充 Modeling MCP 已跑通；若使用降级路径，必须单独标记。
- Desktop 打开后需检查刷新、视觉渲染、切片器交互，以及保存后重新打开。
- 保留原始种子或可恢复副本，避免预览工具或自动化误修改后无法回退。

## 9. 成功标准

以下条件全部满足才判定 V0 Demo 成功：

- Modeling MCP 实际完成语义模型创建或修改。
- 3 张表、2 条关系和 5 个度量值存在且定义正确。
- 关键 DAX 结果与独立计算一致。
- PBIR 自动生成 Overview 页面及规定的 6 个视觉对象。
- Power BI Desktop 无修复性错误地打开 PBIP，并正确显示数据。
- 切片器交互有效，保存、关闭并重新打开后结果仍正常。

若模型成功但 PBIR 或 Desktop 验证失败，应判定为部分成功，不判定为完整链路成功。

## 10. V0 范围外

- Power BI Service 发布、共享、权限、网关和刷新计划。
- 跨机器无配置迁移和数据源凭据自动处理。
- RLS、增量刷新、计算组、复杂时间智能和性能优化。
- 多页面、移动布局、复杂主题、书签、钻取和自定义视觉对象。
- 零种子、零模板创建整个 PBIP 工程壳。
- 产品化 UI、多租户、审计、部署流水线和长期兼容性。

## 11. 已知风险

- Power BI Modeling MCP 和 PBIR 仍可能存在预览期行为或版本变化。
- Modeling MCP 只负责语义模型，不负责报表页面和视觉对象。
- PBIR visual JSON 虽有公开 Schema，实际字段绑定仍需 Power BI Desktop 验证。
- 本地 CSV 路径可能影响项目迁移后的刷新能力。

## 12. 变更约束

- 本文档是后续 V0 执行的默认基线。
- 在用户未明确修改方案前，所有实施步骤、文件组织和验收均按本文档执行。
- 如需改变范围、技术路线或成功标准，应先更新本文档并记录变更，再继续执行。
